# Decision log

Agreed design decisions for netsdk. Add an entry when a decision is made or
changed; don't rewrite history, supersede it.

## Context

Consumers, in order of arrival:

1. **NetBox bootstrap script**: collects data from a few hundred devices
   (run in batches of 5-10 while results are inspected), correlates it and
   populates NetBox. This drives getter priorities.
2. **Config drift checker**: NetBox vs. actual device config.
3. **Ansible on Red Hat AAP**: pushes config (setters phase). The AAP team owns
   their execution environment; we only state the Python minimum.

Packages are internal only and not published. Live tests are manual, on a
separate RHEL 9 machine with device access (git clone, uv; gcc and make for
Genie on 3.14, D32); until 2026-11-10
that was a Windows machine using venv and pip. Development is in RHEL 9 under
WSL2.

## Decisions

| # | Decision | Notes |
|---|----------|-------|
| D1 | Sync API; thread-pool helper for many devices | Not urgent: batches are 5-10 devices. |
| D2 | `requires-python >=3.12`; develop and test on 3.14 | ruff/mypy target 3.12 so newer syntax fails checks. |
| D3 | Hybrid transport ownership | Core defines the contract and ships optional base transports; each device's `open()` composes them or uses its own. |
| D4 | Raw access via separate `get_<noun>_raw()` methods | Not a `raw=True` flag. Returns a mapping of command/endpoint to raw output. |
| D5 | netmiko for SSH | Via `netsdk-core[ssh]`; REST via `netsdk-core[rest]` (httpx). REST-only packages never pull netmiko. |
| D6 | Getter accounts are strictly read-only; we handle the pager ourselves | `terminal length 0` is rejected by AAA command authorization (verified). The SSH transport pages through `--More--` itself. |
| D7 | 0.x versioning; core 1.0 not before FortiGate ships | Device packages pin `netsdk-core>=0.N,<0.N+1`. |
| D8 | Canonical value formats and frozen models | Formats defined in core with the first models. |
| D9 | SDK is NetBox-agnostic | Follow NetBox naming where it is free to do so; diverge whenever it isn't comfortable. No NetBox type mapping in the SDK. |
| D10 | IOS and IOS-XE are fully separate packages | IOS-XE is copied from IOS once IOS is solid, then decoupled. Duplication is tracked in `docs/duplication.md`. |
| D11 | Platform order: IOS, FortiGate, IOS-XE, NX-OS, ASA, WLC, Firepower, F5 | FortiGate second so core sees a REST transport early. |
| D12 | Transport per device decided when we get to it | RESTCONF/NETCONF assumed off; SSH or REST. |
| D13 | Sanitized device output is supplied by Mahak for fixtures | |
| D14 | No CI for now | Lint/type/test locally. |
| D15 | Name stays `netsdk` (placeholder, internal) | `netsdk`, `netsdk-core` were free on PyPI on 2026-11-06. |
| D16 | The SDK sends only commands the caller explicitly asked for | No implicit `terminal length/width`, autodetect, NUL keepalives or extra Enters. The only session-management writes are those in D21. Library defaults that send anything are overridden and covered by tests. |
| D17 | Session logs are mandatory for every device | Full session recorded to a file, secrets redacted. Applies to REST devices too (request/response log). |
| D18 | Auth: password and SSH key both supported | |
| D19 | `send_command()` is public | Documented raw escape hatch alongside getters. |
| D20 | Privilege is controlled by AAA | Assume any `show` command is permitted; no `enable` handling for getters. |
| D21 | SSH session lifecycle | After login, read the prompt passively; send one bare Enter only if none arrives. On close, send `exit` and wait for the device to drop the channel. |
| D22 | SSH host keys: accept and save new, reject changed | Saved to `~/.netsdk/known_hosts` (overridable); `strict_host_keys=True` rejects unknown keys too. No agent, no `~/.ssh` key search: only the credentials given are tried. |
| D23 | Session logs are byte-exact raw captures | Written in binary with netmiko line-ending normalization off, so a sanitized log can become a fixture. `*.raw` fixtures are `-text` in `.gitattributes`. Default dir `session_logs/` (gitignored). |
| D24 | Test helpers ship in core (`netsdk.core.testing`) | Fake CLI for transport/getter unit tests; contract tests will live there too. |
| D25 | Paging is handled, never side-stepped | The SSH PTY size sets the IOS terminal width/length (verified: 511x1000, netmiko's default, which we keep). A height of 0 would disable the pager like `terminal length 0`, so sizes below 1 are rejected. `terminal_height` is configurable; live tests use 24 to force the pager. |
| D26 | No switch stacks: facts model a single chassis | None exist in the environment (2026-11-09). If a parser sees more than one stack member it raises `NotSupportedError` rather than return half the truth. Revisit if stacks appear. |
| D27 | CLI parsing uses ntc-templates (TextFSM) by default, chosen per command | Pure Python, Apache-2.0, works on Windows; already pulled in by netmiko, but declared explicitly by packages that use it. Lives in the parsers layer only: getters map results into our models. Where a template falls short: Genie, per D32 (fix upstream when we can). A template that matches nothing raises `ParseError`. Genie/pyATS rejected for now: no Windows wheels and heavy; revisit per SDK (IOS-XE, NX-OS). Superseded in part by D32, and as the default by D33. |
| D28 | Facts values are reported, not derived | `uptime` is the device's own figure as a `timedelta` (not a boot time from clocks); `os_version` is the string exactly as printed. `CiscoIOS` does not refuse IOS-XE devices: callers who don't care which SDK they use aren't blocked. |
| D29 | Canonical formats (fills in D8) | Defined in `netsdk.core.formats` and enforced by the models: MAC `aa:bb:cc:dd:ee:ff`; speed and bandwidth integer kbit/s (NetBox's unit); duplex `full`/`half`/`auto`; MTU integer. Interface names are full names as the device prints them, never abbreviated. Admin and oper state are separate booleans (`enabled`, `oper_up`); the raw state strings stay on the vendor model. Unknown spellings of optional values are logged and become None, not fatal. |
| D30 | IP addresses: one record per address | `IPAddress(interface, address, secondary, vrf)`; `address` is an `ipaddress` interface (address + prefix), IPv4 or IPv6 so IPv6 can be added without a model change. `vrf=None` is the global table. Unnumbered interfaces get no record: the address belongs to the interface it is configured on. A missing prefix is a ParseError, never assumed /32. VRFs are in use (2026-11-10); IPv6 is not, so getters collect IPv4 only for now. |
| D31 | VLANs and interface-name expansion | `VLAN(vlan_id, name, active, interfaces)`; `active` only for status exactly `active` (shut, suspended and the legacy 1002-1005 `act/unsup` are not); raw status on the vendor model. Ports are access ports only; trunk membership is a separate getter. Abbreviated names (`Gi1/0/1`) are expanded with netutils' `canonical_interface_name`, with per-OS overrides where its canonical spelling differs from the OS (IOS `Vlan`, not `VLAN`); unknown prefixes are logged and kept as printed. A device without VLAN support raises `NotSupportedError`, not an empty list. |
| D32 | Genie parses the commands ntc-templates gets wrong; no hand-written command parsers | Agreed 2026-11-10, once dev and live tests moved to RHEL. ntc-templates stayed the default engine until D33; Genie (pyATS, Cisco, Apache-2.0) was used per command: IOS `show vtp status` (the template misreads v3 "Primary Server" and the old v1 layout). Hard dependency of each Cisco package that uses it, never an optional extra, so no getter silently depends on what was installed. Called through `netsdk.core.parsing.parse_genie()` with already-collected text: Genie never connects or sends anything (D16). Its `parse()` validates against Genie's schema; any Genie exception or empty result becomes `ParseError`. Unit-test expectations are written from the raw samples, not copied from Genie's. Pinned `>=26.10,<27`. Linux/macOS only. On Python 3.14 genie-libs-sdk pins ruamel.yaml.clib to a release without a glibc wheel, so installs need `gcc` and `make`. Values Genie gets wrong are dropped, not repaired: the VTP MD5 digest (Genie sorts its bytes). |
| D33 | Genie is the default CLI parser engine; ntc-templates is the fallback | Agreed 2026-11-10 (supersedes D27's default). New getters use Genie; ntc-templates only where Genie has no parser or gets the command wrong, recorded per command below. The D32 rules hold for both engines: called with already-collected text, every failure is a `ParseError`, expectations written from raw samples, values an engine gets wrong are dropped, not repaired. Genie returns interface names already expanded and in its own order (not the device's); names still go through `full_interface_name()`. Engines per IOS command: Genie for `show vtp status`, `show interfaces switchport`, `show cdp neighbors detail`; ntc-templates for `show lldp neighbors detail` (D35), `show inventory` (D36), `show ip interface` (D37), `show version`, `show interfaces`, `show vlan brief` (live-verified before D33; each moves to Genie only with a new live check). Compared 2026-11-13 on the fixtures, none of those moves: Genie misses the reload reason on old IOS and gives uptime unsplit (`show version`), merges a repeated interface silently for one extra media type (`show interfaces`), has no `show vlan brief` parser and rewrites VLAN status, and doesn't mark unnumbered interfaces (`show ip interface`). `show interfaces trunk` is not used yet: Genie drops the continuation lines of a wrapped VLAN list, and ntc-templates has no IOS template. Deferred to the NX-OS SDK (2026-11-10): no IOS switch here has an allowed list long enough to wrap; some Nexus switches do, so real samples come from there. |
| D34 | Switchports: one record per layer-2 port | `Switchport(interface, mode, access_vlan, native_vlan, all_vlans_allowed, allowed_vlans)` in core; routed ports get no record. `mode` is the operational mode, `access`/`trunk` or None (down, private VLAN, ...); raw admin/oper strings on the vendor model. Allowed VLANs as configured, whatever the mode: `all_vlans_allowed` for "ALL" (not expanded), otherwise a sorted tuple of IDs, `()` for "NONE" and None when not printed. No VLAN (`none`, `unassigned`, `0 (Inactive)`) is None. Ranges expanded with netutils. IOS names `Hu` and `Wl` expand to `HundredGigE` and `Wlan-GigabitEthernet` (netutils differs; amends D31). |
| D35 | Neighbors: one getter for CDP and LLDP, one record per neighbor per local port per protocol | Agreed 2026-11-10; both protocols are in use, either may be off on a device. `Neighbor(protocol, local_interface, remote_name, remote_port, remote_port_description, remote_chassis_id, remote_platform, remote_description, management_addresses, capabilities)` in core. Remote values exactly as advertised (no name expansion, no MAC normalization: we don't know the neighbor's OS; NX-OS names keep their `(serial)`); matching them to NetBox is the consumer's job. Capabilities are lowercase names; LLDP codes expanded with the legend IOS prints. `local_interface` is None only where IOS doesn't print it (some releases' LLDP detail), logged. Engines: Genie for CDP (ntc-templates silently drops the second link to the same neighbor); ntc-templates for LLDP (Genie empties non-Cisco system descriptions, rewrites remote port IDs and keys neighbors by name). The LLDP template keeps the first description line and one IPv4 management address. `% CDP/LLDP is not enabled` and `% Invalid input` mean no neighbors from that protocol (logged); NotSupportedError only when neither command exists. The closing `Total ... entries displayed: N`, when printed, must equal the records parsed, so a dropped record is a ParseError; some IOS releases don't print it (verified live 2026-11-10), so it is not required, and empty output means no neighbors. Hold time is not collected: it changes every second. |
| D36 | Inventory: ntc-templates with a corrected copy of its template until upstream releases the fix | Agreed 2026-11-10. Neither engine is right as released: Genie's `ios` parser crashes on IOS-XE (incl. the 3850 sample), its `iosxe` parser crashes on classic IOS and drops 53 of 311 items, and it keys items so identical modules overwrite each other; ntc-templates 9.3 lists every item but cuts serials at the first `-` (46 of 376 items: AOC/DAC and breakout cables, whose four legs then share one serial) and part IDs at a space. `netsdk/cisco/ios/templates/cisco_ios_show_inventory.textfsm` is upstream's template (master b663a8a) with the two `Value` lines fixed, sent upstream as networktocode/ntc-templates#2377; `parse_textfsm(template=...)` uses it. A test asserts the released template still truncates: when it fails, delete the copy. Template overrides are a last resort, each listed here with its upstream PR. `InventoryItem(name, description, part_id, version_id, serial_number)` in core, values as printed, every item kept in device order (names repeat; a 7206VXR prints an empty chassis name, so `name` may be None). |
| D37 | `show ip interface`: corrected template copy for the tunnel transport VRF | Agreed 2026-11-13. A tunnel with `tunnel vrf X` prints `Tunnel VPN Routing/Forwarding "X"`: the VRF its encapsulated packets use, not the interface's. The released template's `^.+VPN\s+Routing/Forwarding` matched it, so tunnel addresses in the global table were reported in VRF X (the live check passed because the tested devices had no such tunnels). Fixed like D36: `netsdk/cisco/ios/templates/cisco_ios_show_ip_interface.textfsm` is the 9.3.0 template plus one rule that consumes the tunnel line, sent upstream as networktocode/ntc-templates#2378; a test fails once a release has it. Genie reads the VRF correctly but was not chosen: it doesn't mark unnumbered interfaces and can copy the borrowed address with its prefix, which would break D30 without our own per-interface check. |
| D38 | NX-OS: SSH CLI with `\| json` output; text parsing only where JSON is missing | Agreed 2026-11-13. New package `packages/cisco-nxos` (`netsdk.cisco.nxos`) on the core `SSHTransport`, same rules as IOS (D16, D25, session logs). NX-API is not enabled anywhere, so not used (D12). Commands are sent with `\| json` where the device supports it; Mahak checks each command by hand on the bench before it is implemented, since support varies by command and release. Commands without JSON fall back to Genie, then ntc-templates (D33). NX-OS JSON nests rows as `TABLE_x`/`ROW_x` and gives a single row as an object instead of a list: one helper normalises that (`rows()` in the NX-OS parsers). JSON is read by `netsdk.core.parsing.parse_json`: lines before the object (9.3 prints `SB: Permission denied.` / `drbg_instantiate failed` ahead of every `| json` output, never inside it) are logged at INFO and ignored; no object, a broken or cut-short one, or anything after it is a `ParseError`. NX-OS hard-wraps one-line JSON at the terminal width (511, its maximum), inside strings too (live on 10.5, 2026-11-13), so `parse_json` removes every line break inside the object before decoding: JSON never needs a newline between tokens and a raw newline inside a string is invalid, so a newline is either indentation or a wrap break. The NX-OS transport scans 8 lines for errors so a rejection after that noise is still seen. The pager is always assumed (Mahak: plan for it even where it hasn't shown up); `render_terminal` handles `ESC[K` and drops other ANSI escapes in case the prompt is drawn in reverse video. `get_facts()` takes model and serial from the `Chassis` entry of `show inventory | json` (10.5 puts literal quotes around `name` and `desc` in the JSON, e.g. `"\"Chassis\""`; matched either way. Agreed 2026-11-13: getters return such values with one surrounding pair of quotes removed (inner quotes kept); fixtures and live-test diagnostics keep the raw data as printed), not from `show version`, whose board ID is not the chassis serial on modular switches, which may be added later (Mahak, 2026-11-13). Releases in use: 9.3(9), 10.2(5), 10.4(5), 10.5(4), and 7.3(11)N1(1) (Nexus 5500/5600/6000 train, oldest JSON support). n9000-14.2(5l) is the ACI switch image, not standalone NX-OS: out of scope (Mahak, 2026-11-13). No Nexus 7000, so no VDCs to handle. FEX is attached to some switches: FEX ports are expected among the parent's interfaces; a FEX getter comes later. Every getter that reads per-VRF data asks for all VRFs (`vrf all`), because NX-OS shows only `default` otherwise and every Nexus has a `management` VRF. |
| D39 | NX-OS interfaces: mapped by field set, not by name | Agreed 2026-11-13. `show interface \| json` reports each interface with one of two field sets: `svi_*` (SVIs) or `state`/`eth_*` (Ethernet, port-channel, `mgmt0`, FEX ports, and others seen so far). The set present decides the mapping; an interface with neither is a `ParseError` naming its field names (never values), so a new type shows up instead of being guessed. Live 2026-11-13: Ethernet, port-channel, loopback and `mgmt0` use the eth set, `Vlan` the svi set; loopbacks have no MAC, speed, duplex or mode, `mgmt0` no mode or reason, and those come back None. Other types (nve, tunnel, FEX, ...) are expected on other switches; nothing is keyed on the name. `enabled` is `admin_state == up`; 7.3(11)N1(1) prints no `admin_state` (live, 2026-11-13), so there a port is disabled only when it is down with the reason `Administratively down`, NX-OS's own wording for a shut port; `oper_up` only for `state == up` (other values are reasons). Names are used as printed: NX-OS JSON prints full names. Speed `auto-speed` is None; unknown speed or duplex spellings are logged, not fatal (as IOS). `NXOSInterface` adds `state_reason`, `hardware_type`, `burned_in_address`, `bandwidth`, `port_mode`. Descriptions are returned as printed: the D38 quote rule applies only to fields NX-OS is known to quote. |
